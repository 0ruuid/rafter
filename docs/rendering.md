# 布局与交互

## Canvas

图片、文字和点击区分别配置，按声明顺序叠放。文字范围按实际字体度量计算，点击区按渲染后的覆盖范围定位。

点击区跟随的元素隐藏时，点击区也失效。禁用的上层点击区仍会阻挡下层交互。

Canvas 的 `type: item` 是叶节点：`item` 可引用 `minecraft:...` 材料或已注册的
`ItemProvider`，`size` 使用 18 的整数倍且不超过 864，图标按 16×scale 绘制，数量区域另行预留。
`x` 可为任意像素，`y` 使用 9px 对齐；`show-count`、`show-tooltip`、`actions`、`tooltip`、
`visible`、`enabled` 和 `variants` 沿用叶节点规则。`show-count` 不修改原始 `ItemStack`，物品叶节点
不是容器，也不声明拖拽能力。真实 `ItemStack` 的默认 tooltip 由引擎绑定。
数量使用实际堆叠数量，不绘制原版耐久条和冷却遮罩。槽位底图、边框、角标和选中态由既有图片、文字与条件组合；悬停目前只提供 tooltip，不提供客户端悬停换图。物品模型使用原生渲染层，不支持任意贴图遮挡模型或局部裁剪。

已为 1.21.6–1.21.11、26.1–26.1.2、26.2 和 26.3 提供对应的资源格式与 Shader 适配。
版本声明由 `ClientRenderProfiles` 统一导出，未知协议不自动放开。物品布局的客户端实测目前只有 26.2；
其他版本的源码适配、离线检查不能代替实机验收。item popup、原生 modal 内 item 和滚动物品页仍不支持。
页面须整体放入视口，不承诺任意 GUI 缩放。原生物品载体每条占 20px，最小 GUI 高度以 `item-layouts.json` 的导出值为准：
`minimumGuiHeight = 63 + count * 20 + CanvasHeight + 8 + 30 + 5`。
路由通道由原生物品宽度 1..256 的整数居中编码给出，全局最多 128 个；为避免不同页面的角点误匹配，部分通道不能同时使用。展开超限时构包明确报错，不静默丢弃物品。

## 原生控件

正文、输入和操作区按客户端规则排列，可调整支持的宽度与区域内顺序。`native-body-position` 控制正文在画布前后的位置，`select` 通过点击循环切换选项。

Native 物品尺寸和原生流式排版不变；Native 只新增 `show-tooltip`，不新增 `size` 或 `show-count`
（原版 `show_decorations` 无法只控制数量）。

## 模态页

弹窗由已成功显示的纯 Canvas 页打开，或由当前模态页同层替换；交互由弹窗接管。首次 Canvas→modal 复用真实 Canvas 背景，同层 modal 替换复用同一背景且不追加历史，`back` 一次回到原 Canvas 或 popup。

- `modal.top` 设置面板上方留白，`content-top` 设置原生内容起点，标题坐标相对面板。
- 输入、标签、计数、按钮和反馈由同一套布局定位。
- 输入页用固定的 `feedback` 目标显示错误。
- 多行输入放在最后，计数显示在输入框外。
- 面板贴图只画装饰，输入框使用原生控件；调整控件高度时同步检查面板尺寸。
- 表单只有显式 `submit` 才校验并写入声明状态；Esc、关闭或返回不会自动保存原生输入。

资源加载是生效前提。布局或 `size` 这类静态变化需要重建资源包并让客户端重新加载；数据、条件和分页变化只需重新加载菜单，不要求重建资源包。
